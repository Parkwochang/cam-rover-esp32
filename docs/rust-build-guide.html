Rust on ESP32-CAM

소스에서 로봇까지,
무엇이 어디서 실행될까?

이 프로젝트는 Mac에서 Rust와 ESP-IDF로 펌웨어를 빌드하고, 결과를 ESP32-CAM에 기록합니다. 로봇을 움직이는 프로그램은 ESP32 칩에서 실행됩니다.

.embuild = ESP-IDF 빌드 도구와 SDK
target = 중간 결과와 펌웨어
NVS = 집 Wi-Fi 설정 저장

빌드와 실행 흐름

단계를 누르거나 재생을 누르면 각 도구가 무엇을 만드는지 볼 수 있습니다. 화살표는 파일과 실행 위치가 이동하는 방향입니다.

Mac에서 작성 → USB로 기록 → ESP32에서 실행

설정과 빌드 결과

Cargo.toml
Rust 패키지, 의존성, ESP-IDF 5.4.3과 카메라 컴포넌트 지정.
.cargo/
이 저장소의 타깃, 링커, 실행 명령 설정. 사용자 홈의 ~/.cargo/ 설치 폴더와는 다름.
.embuild/
첫 빌드 때 내려받은 ESP-IDF, C 컴파일러, Python 환경 등의 내부 작업 폴더. 펌웨어 파일이 아님.
target/
Cargo 빌드 산출물. target/xtensa-esp32-espidf/release/cam-rover-esp32가 업로드할 ELF.
*.bin
espflash save-image --merge로 별도 생성한 통합 플래시 이미지. 일반 espflash flash에는 ELF를 사용해도 됨.

설치해야 할 도구

로봇 펌웨어 빌드 기준입니다. 이 Mac에는 아래 Rust/ESP 도구가 이미 설치되어 있습니다. 새 Mac에서 저장소를 내려받았다면 한 번 설치해야 합니다.

필수

  • Apple Command Line Tools — C 컴파일에 필요한 기본 개발 도구.
  • rustup · Cargo — Rust 툴체인과 패키지 빌드 명령.
  • espup — ESP32의 Xtensa 전용 Rust 컴파일러 설치.
  • ldproxy — Rust와 ESP-IDF C 라이브러리의 최종 링크.
  • espflash — USB 직렬 포트를 통해 ESP32에 기록.

직접 설치할 필요 없음

  • Arduino IDE — 이 프로젝트는 Cargo와 ESP-IDF를 사용합니다.
  • ESP-IDF SDK · Python 가상환경 · C 도구 — 첫 빌드 때 .embuild/ 아래로 자동 준비됩니다.
  • CH340 드라이버 — USB 직렬 포트가 나타나지 않을 때만 확인합니다.

Mac 터미널에서 실행하는 순서

  1. 새 Mac에서 도구 설치 · 최초 1회

    저장소의 rust-toolchain.toml이 esp를 지정하므로, 설치 명령에는 +stable을 붙이면 새 환경에서도 순서가 꼬이지 않습니다. Apple 개발 도구는 없을 때만 설치하세요.

    xcode-select --install  # 이미 설치돼 있으면 생략
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"
cargo +stable install espup --locked
espup install
cargo +stable install ldproxy --locked
cargo +stable install espflash --locked

  2. 현재 셸에 ESP 환경 적용

    espup이 생성한 환경 파일을 새 터미널마다 불러옵니다.

    source "$HOME/.cargo/env"
source "$HOME/export-esp.sh"

  3. 프로젝트에서 release 빌드

    처음에는 ESP-IDF와 카메라 컴포넌트를 받느라 오래 걸립니다. 이후 빌드는 바뀐 부분만 다시 처리합니다.

    cd /Users/changwoo/Desktop/project/cam-rover-esp32
cargo build --release

  4. USB 포트 확인 후 업로드

    아래 포트 이름은 실제로 확인했던 예시입니다. 다시 연결하면 번호가 달라질 수 있으므로 먼저 목록을 확인하세요. 자동으로 다운로드 모드에 들어가지 않으면 BOOT를 누른 채 RESET을 한 번 누르고 다시 업로드하세요. 완료 후 BOOT에서 손을 떼고 RESET을 누릅니다.

    espflash list-ports
espflash flash --port /dev/cu.usbserial-1410 \
  target/xtensa-esp32-espidf/release/cam-rover-esp32

  5. 대안: Cargo 명령 하나로 빌드·업로드·로그 보기

    위의 빌드와 업로드 명령 대신 사용할 수 있습니다. 이 저장소의 .cargo/config.toml이 espflash flash --monitor를 runner로 지정하므로, cargo run은 Mac에서 로봇 프로그램을 실행하는 명령이 아닙니다. 포트가 여러 개면 선택을 요청할 수 있습니다.

    cargo run --release

  6. 선택: 직렬 로그와 통합 BIN

    로그 확인과 배포용 통합 이미지는 필요할 때만 실행합니다. save-image는 기존 ELF를 BIN으로 포장하며 다시 컴파일하지 않습니다.

    espflash monitor --port /dev/cu.usbserial-1410 \
  --elf target/xtensa-esp32-espidf/release/cam-rover-esp32

espflash save-image --chip esp32 --merge \
  target/xtensa-esp32-espidf/release/cam-rover-esp32 \
  target/xtensa-esp32-espidf/release/cam-rover-esp32.bin

핵심: USB 케이블 연결에는 빌드가 필요 없습니다. 소스를 변경해서 새 펌웨어를 넣을 때만 다시 cargo build --release 후 업로드합니다.

보드 내부의 세 가지 핵심 흐름

아래 그림은 현재 펌웨어 구현을 기준으로 합니다. 휴대폰에서는 그림 안쪽을 가로로 스크롤할 수 있습니다. 주황색은 각 그림에서 가장 중요한 상태나 경로만 강조합니다.

라즈베리 파이에서 보내는 HTTP 명령 예시

집 Wi-Fi 연결 후 공유기 DHCP 목록 또는 USB 직렬 로그에서 로봇 IP를 확인하세요. ROVER_IP를 해당 주소로 바꾸면 됩니다. 이동 명령은 700ms보다 자주 반복하고 버튼을 놓을 때 정지를 보내세요.

curl "http://ROVER_IP/api/move?direction=forward"
curl "http://ROVER_IP/api/move?direction=stop"
curl "http://ROVER_IP/api/network"
curl -X POST "http://ROVER_IP/api/network" -H 'Content-Type: application/json' \
  -d '{"mode":"sta","ssid":"YOUR_2_4_GHZ_SSID","password":"YOUR_PASSWORD"}'
curl -X POST "http://ROVER_IP/api/network" -H 'Content-Type: application/json' \
  -d '{"mode":"ap"}'

모드 변경 요청은 HTTP 202를 반환한 뒤 보드를 재부팅하므로 기존 IP 연결이 끊깁니다. GET /api/network는 현재 모드·IP·복구 여부를 반환하며 암호는 반환하지 않습니다. 집 Wi-Fi 접속 실패 시 cam-rover에 연결해 http://192.168.71.1에서 다시 설정할 수 있습니다.

헷갈리기 쉬운 점

.cargo와 ~/.cargo는 같은 곳인가요?

아니요. 프로젝트의 .cargo/config.toml은 이 펌웨어의 타깃 설정입니다. 사용자 홈의 ~/.cargo/bin에는 Cargo와 espflash 같은 실행 도구가 설치됩니다.

cargo run은 Mac에서 로봇 프로그램을 실행하나요?

아니요. 이 프로젝트의 실행 대상은 xtensa-esp32-espidf이고, 설정된 runner는 espflash flash --monitor입니다. 따라서 실행 단계는 보드 업로드와 직렬 모니터로 이어집니다.

웹 조종 화면은 어디에 저장되나요?

src/web/index.html은 Rust의 include_str!로 펌웨어에 포함됩니다. 보드의 HTTP 서버가 이를 휴대폰 브라우저로 전송합니다.

집 Wi-Fi 접속이 실패하면 조종할 수 없나요?

연결 실패 시 로봇은 cam-rover AP를 다시 만듭니다. 휴대폰을 그 AP에 연결하고 http://192.168.71.1을 열어 SSID와 암호를 다시 설정하세요. 연결 정보는 NVS에 남아 있으며, 선호 모드가 STA라면 다음 재부팅 때도 접속을 다시 시도합니다.

카메라 드라이버가 C이면 Rust 프로젝트가 아닌가요?

프로그램의 제어 흐름은 Rust에 있습니다. 카메라와 모터의 저수준 하드웨어 호출만 ESP-IDF C API를 통해 연결합니다. Rust 코드가 C 함수를 호출하도록 .h 선언에서 바인딩이 생성됩니다.
